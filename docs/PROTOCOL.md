# QCP Protocol Specification v0.1

**颠覆 KCP 的协议层创新**

---

## 1. KCP 的根本问题

KCP 本质是 "跑在 UDP 上的 TCP"：
- ARQ (Automatic Repeat reQuest) = 每个丢包都要重传
- 拥塞控制 = TCP 那套慢启动
- 固定头 = 24 bytes，没有灵活性
- 无 FEC = 丢包只能等

**结论：用 TCP 的思路做 UDP，永远超不过 TCP。**

---

## 2. QCP 协议创新：抛弃 ARQ

### 2.1 核心理念：FEC-First

```
KCP: 发送 → 丢包 → 等超时 → 重传 → 等ACK → 收到
QCP: 发送 + FEC冗余 → 丢包 → FEC解码恢复 → 完成
```

**QCP 不需要 ARQ，FEC 就是可靠性。**

### 2.2 包格式设计

```
KCP 包头 (24 bytes):
┌─────────┬─────────┬─────────┬─────────┐
│ conv    │ cmd     │ frg     │ wnd     │  4+1+1+2 = 8 bytes
├─────────┼─────────┼─────────┼─────────┤
│ ts      │ sn      │ una     │ len     │  4+4+4+4 = 16 bytes
└─────────┴─────────┴─────────┴─────────┘

QCP 包头 (10 bytes, 可变长):
┌─────────┬─────────┬─────────┐
│ flags   │ stream  │ seq     │  1+1+2 = 4 bytes
├─────────┼─────────┼─────────┤
│ fec_id  │ ts_diff │ payload │  1+2+var = 3+ bytes
└─────────┴─────────┴─────────┘
```

**QCP 头更小，信息更紧凑。**

### 2.3 Flags 字段 (1 byte)

```
Bit 7: DATA     - 数据包
Bit 6: FEC      - FEC 冗余包
Bit 6: PRIORITY - 高优先级 (关键游戏数据)
Bit 5: BURST    - 突发标记
Bit 4: MIGRATE  - 连接迁移
Bit 3-0: 保留
```

### 2.4 流量控制：三通道模型

```
KCP: 单一 FIFO 队列
QCP: 三通道并行

┌─────────────────────────────────────┐
│  Channel 0: CRITICAL (射击/技能)    │ ← 最高优先级，零延迟
├─────────────────────────────────────┤
│  Channel 1: REALTIME (移动/AOI)     │ ← 正常优先级
├─────────────────────────────────────┤
│  Channel 2: BATCH (聊天/日志)       │ ← 低优先级，可延迟
└─────────────────────────────────────┘
```

### 2.5 FEC 方案：自适应 Reed-Solomon

```
KCP: 无 FEC，纯 ARQ
QCP: 动态 FEC 冗余率

丢包率 0-2%:   FEC 5%   (几乎无开销)
丢包率 2-5%:   FEC 10%  (平衡)
丢包率 5-10%:  FEC 20%  (可靠)
丢包率 10-20%: FEC 30%  (极端)
```

### 2.6 连接迁移：零感知切换

```
KCP: 网络切换 = 断开重连
QCP: 网络切换 = 无缝迁移

WiFi → 4G 切换过程:
1. 检测到 WiFi 信号弱
2. 预建立 4G 连接
3. 双路并行发送 (冗余)
4. WiFi 断开后，4G 无感接管
```

### 2.7 拥塞控制：AI 预测

```
KCP: TCP Reno/Cubic
QCP: ML 预测模型

输入:
- RTT 历史序列
- 丢包率变化趋势
- 带宽利用率
- 时间特征 (游戏高峰期)

输出:
- 最优发送速率
- 最优 FEC 冗余率
- 预测未来 100ms 网络状态
```

## 3. 数据流架构

### 3.1 Zero-Copy Ring Buffer

```
KCP: 每次发送 → 分配内存 → 拷贝数据 → 发送 → 释放
QCP: 预分配环形缓冲区 → 直接写入 → 发送 → 无释放

┌─────────────────────────────────────┐
│  Ring Buffer (64KB)                 │
│  ┌───┬───┬───┬───┬───┬───┬───┬───┐ │
│  │ P1│ P2│ P3│ P4│ P5│ P6│ P7│ P8│ │
│  └───┴───┴───┴───┴───┴───┴───┴───┘ │
│         ↑ write     ↑ read          │
└─────────────────────────────────────┘
```

### 3.2 Lock-Free 队列

```
KCP: Mutex 保护发送/接收队列
QCP: 无锁队列 (CAS 操作)

发送端: 原子写入 → 无等待
接收端: 原子读取 → 无等待
```

### 3.3 批量处理

```
KCP: 1 包 1 处理
QCP: 批量处理

收集 10ms 内的所有包 → 一次性 FEC 编码 → 一次性发送
减少系统调用次数: 100次/10ms → 1次/10ms
```

## 4. 与 KCP 的本质区别

| 维度 | KCP | QCP |
|------|-----|-----|
| 可靠性机制 | ARQ (重传) | FEC (纠错) |
| 丢包处理 | 等待超时 + 重传 | 实时解码恢复 |
| 包头开销 | 24 bytes | 10 bytes |
| 队列模型 | 单一 FIFO | 三通道优先级 |
| 内存管理 | 每次分配 | 预分配 Ring |
| 锁竞争 | Mutex | Lock-free |
| 拥塞控制 | TCP Reno | AI 预测 |
| 网络切换 | 断开重连 | 无缝迁移 |
| 批量发送 | 不支持 | 10ms 批次 |
